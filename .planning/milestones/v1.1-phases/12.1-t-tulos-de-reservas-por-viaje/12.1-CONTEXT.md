<domain>
## Phase Boundary

`app/components/ReservasSection.vue` has three headings hard-coded for Roma:
- line 73, «✅ Ya reservado · 3 comensales», sitting above the `mesas` list;
- line 81, «🎟️ Visitas y entradas reservadas», sitting above the `visitas` list;
- line 91, «Restaurantes · cuándo reservar y con cuánta antelación», the `.reservas-box-header` above the table.

Campania (Phase 13) needs its own headings, because it lists flights, ferries, beds, the car and concerts, not restaurant bookings for three people. This phase makes those headings data-driven per trip, **with Roma's exact strings as defaults**, and stops rendering a confirmed group that has no entries.

**Out of scope:**
- Any Campania content. Phase 13 writes `content/trips/campania/reference/reservas.yml`.
- New `group` enum values.
- Any visual or CSS change.
</domain>

<decisions>
## Implementation Decisions

- **D-01 — Shape.** Add an optional `headings` object to `ReservasSchema` **and** to the flat `ReferenceRowSchema` superset (`shared/schemas.ts:401-429`). Without the superset, Content materialises the column as null.
  - Shape: `headings?: { mesas?: string, visitas?: string, table?: string }`.
  - The object is `z.strictObject`, so a misspelled key fails validation instead of being silently stripped. zod 4 strips unknown keys by default, the same pitfall as Phase 12 `ChoiceRow`.
  - Values are plain strings, rendered by interpolation exactly as today. They are not Markdown, and there is no `v-html`.
  - The field name `headings` avoids Content-reserved names (`meta`, `id`, `title` collisions).
  - **Reversibility:** reversible.
- **D-02 — Defaults are Roma's literal strings**, defined once, for example as a `RESERVAS_HEADINGS_DEFAULT` constant next to the component or in `app/utils/`:
  - `mesas` = «✅ Ya reservado · 3 comensales»
  - `visitas` = «🎟️ Visitas y entradas reservadas»
  - `table` = «Restaurantes · cuándo reservar y con cuánta antelación»

  Roma's `reservas.yml` is **not edited**: it has no `headings`, so it gets the defaults and its DOM is byte-identical. That includes whitespace and the inline `style="margin-top:.7rem;"` on the second `h4`.
- **D-03 — Empty groups.** The `h4` and the `ul` of a confirmed group render only when that group has at least one entry.
  - Roma has entries in both groups, so its DOM does not change.
  - When the first group is empty, the second `h4` keeps its current inline margin. This is planner discretion, but no CSS file changes and no `<style scoped>`.
  - When both groups are empty, the `.reservas-confirmadas` block is not rendered.
  - The table and its header are unchanged. The header text comes from `headings.table`.
- **D-04 — `group` keeps its two values (`mesas | visitas`).** The two values act as the first and second confirmed blocks. Phase 13 retitles them, for example «✈️ Vuelos, barcos y coche» and «🎟️ Conciertos y entradas». The schema comment documents this. No enum is renamed: that would be a Roma content migration.
- **D-05 — Tests.**
  - A schema test: `headings` is accepted, a misspelled key is rejected, and the field is present in `ReferenceRowSchema`.
  - A component or unit test of the rendering: defaults with no `headings`; custom headings; an empty group not rendered. Prefer `mountSuspended` or a pure helper.
  - The parity gate stays 110/110 with **no** `--update-snapshots`, and `tests/parity/render-reference.spec.ts` is not edited.
  - A dev E2E is optional. Campania has no `reservas.yml` until Phase 13, so the planner may use the `prueba` or `forma` draft trip **only if** that does not require editing their content (D-06). Otherwise, unit tests are enough.
- **D-06 — Frozen files** (milestone rule):
  - No golden is re-baselined, and no `tests/parity/` spec is edited.
  - `content/trips/{roma,prueba,forma,campania}` are not touched.
  - `app/assets/css/{base,tokens,fonts,leaflet}.css` are not changed.
  - No `<style scoped>` and no new `v-html`.
  - All fields are `.optional()`.
- **D-07 — Process.**
  - Node 22 (`~/.nvm/versions/node/v22.20.0/bin`).
  - `rm -rf .data .nuxt .output` before generate.
  - Never run `test:trips` at the same time as generate or verify.
  - Branch `release/nuxt-4`.
  - Sequential execution.
  - Commits end with the Co-Authored-By trailer.
  - One plan is expected (small phase).
