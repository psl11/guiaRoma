### WR-01: Non-Roma trips silently inherit Roma's headings, and only a README note guards against it

**Files modified:** `tests/data/trips.ts`, `tests/data/invariants.spec.ts`, `tests/README.md`
**Commit:** 1c71a83
**Applied fix:**
- New data-gate rule `reservas-headings` in `tests/data/trips.ts` (added to `RULES`, so the live gate runs it on every trip). The rule applies to every trip other than `roma` that has `reference/reservas.yml`. It requires `headings.table`, because the table header always renders. It also requires `headings.<group>` for each `confirmed` group that has entries.
- A value that is missing, `null`, not a string, or whitespace only counts as missing.
- The violation names the culprit `reservas.yml` and quotes the Roma text the trip would inherit, for example `falta headings.table: heredaría el texto de Roma («Restaurantes · …»)`.
- Teeth tests are in memory, in the same style as `stay-ref`: both groups with no headings gives three violations; forgetting only `table` (the Campania case from the review) gives one; `null` and whitespace-only values count as missing; an empty group does not need a heading; Roma is exempt.
- The existing anchor fixture `validReservas` (trip `prueba`) now declares `headings.table`, because the new rule correctly requires it.
- No schema change and no content change (D-06). Only Roma has a `reservas.yml` today, so the live gate stays green.
- README: added the rule to §5.3 and §5.9, and the Phase 13 note now points at the gate.

### WR-02: A heading made only of spaces passes validation and renders as an empty `h4`

**Files modified:** `shared/schemas.ts`, `app/utils/reservasHeadings.ts`, `tests/data/schema.spec.ts`, `tests/unit/reservasHeadings.spec.ts`, `tests/README.md`
**Commit:** 93684c1
**Applied fix:**
- Schema: the shared `ReservasHeadings` now uses `HeadingText = z.string().min(1).regex(/\S/, 'encabezado vacío (solo espacios)')`, so both `ReservasSchema` and `ReferenceRowSchema` get it.
- Resolver: `resolveReservasHeadings` falls back to Roma's text when the value is `trim() === ''`. A custom value is returned untrimmed, so it keeps its bytes. Roma uses the defaults, so its output is unchanged.
- Tests: `schema.spec.ts` rejects `'  '`, `'\n'` and `' \t '` (the message contains «encabezado vacío»), rejects the same in `ReferenceRowSchema`, and accepts `' Qué reservar '`. `reservasHeadings.spec.ts` checks that whitespace values fall back to the default and that a custom value with surrounding spaces is not trimmed.

### WR-03: The D-03 empty-group rendering is not tested, and the wiring scan passes when the `v-if`s are misplaced

**Files modified:** `tests/unit/reservasHeadings.spec.ts`, `tests/README.md`
**Commit:** c2bea21
**Applied fix:** I used the no-dependency route. `vue`, `@vue/compiler-sfc` and `vue/server-renderer` are not resolvable from the project root under pnpm's strict layout, so an SSR render would have needed a new direct dependency.
- `confirmedBlocks` reads each `h4`/`ul` of `ReservasSection.vue` as an element: its own `v-if`, the `headings.<k>` it renders, and the list its `v-for` iterates.
- `bindingProblems` requires the order `h4,ul,h4,ul`. Each element's `v-if` must be its own group's `<group>.length`, matching its heading key or `v-for` list. The `.reservas-confirmadas` div must carry `mesas.length || visitas.length` and contain all four elements.
- `renderConfirmed` evaluates the real template's `v-if`s with `confirmedGroup` and labels each rendered element by its content, not by its condition:
  - visitas only → `['h4 visitas', 'ul visitas']`
  - mesas only → `['h4 mesas', 'ul mesas']`
  - both → all four, in order
  - `confirmed: []` → `null` (no block)
- Teeth mutate the real template in memory:
  - Swapping the two `h4` `v-if`s: the old substring scan still passes (asserted), the new scan reports both, and the render becomes `['h4 mesas', 'ul visitas']`.
  - A `ul` of mesas iterating `visitas`.
  - A block gated on a single group.
- The tautological `confirmed: []` test was removed. `package.json` and `pnpm-lock.yaml` are unchanged.
- **Requires human verification:** the scan is static. It is not a real DOM render, so the in-browser empty-group check still arrives with Campania's `reservas.yml` in `test:trips` (Phase 13).
