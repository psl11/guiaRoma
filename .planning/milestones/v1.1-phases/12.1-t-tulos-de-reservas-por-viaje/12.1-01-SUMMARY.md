# Phase 12.1 Plan 01: Títulos de Reservas por viaje Summary

**Strict optional `headings { mesas, visitas, table }` on reservas.yml, with Roma's texts defined once as defaults in `app/utils/reservasHeadings.ts`. Empty confirmed groups now render no heading or list. Roma's `#reservas` HTML is byte-identical to the pre-change build.**

## Accomplishments

- `ReservasHeadings` (`z.strictObject`, each key `z.string().min(1).optional()`) is shared by `ReservasSchema` and the flat `ReferenceRowSchema` superset. Because the superset has it, Content materialises the column and the `unknown-key` rule accepts it. The D-04 comment documents `mesas`/`visitas` as the first and second confirmed block.
- `ReservasSection.vue` takes its three headings from `resolveReservasHeadings(...)` and its groups from `confirmedGroup(...)`. `.reservas-confirmadas` gets `v-if="mesas.length || visitas.length"`, and each `h4`/`ul` gets its own `v-if`. The second `h4` keeps the static `style="margin-top:.7rem;"`. The template has no `<MDC>` on headings, no `v-html` and no style block.
- The fixture was measured before editing. The second `h4` and `.reservas-box-header` come out as `" texto "` (one space on each side, from Vue condensing the old multiline static text); the first `h4` has no spaces. The template reproduces this with `{{ ` ${headings.visitas} ` }}` / `{{ ` ${headings.table} ` }}`. The byte comparison passed on the first generate.
- The new tests have teeth. Schema: a misspelled key gives `Unrecognized key: "mesa"`, and the `z.strictObject` -> `z.object` mutation turns the spec red. The unit spec covers the helpers plus a static wiring scan with in-memory teeth.
