# Phase 3 — UI Design Contract

> Visual and interaction contract for the page/layout/theme phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PARITY-BY-CONSTRUCTION PHASE.** The design system already exists verbatim in code (`app/assets/css/tokens.css` + `base.css`) and in the live `index.html`. This contract does **not invent** values — it **pins the existing ones as LOCKED** and traces every component to its source lines. Any new value would be a parity regression. The 1.0 bar is "exactamente igual que la guía de hoy" (100% visual + functional parity).
>
> **F3 scope only** (see `<scope>` below). Card/timeline/reference rendering + pace modes → F4. Cross-nav (scrollspy, back-stack, `.nav-pill.active`, `a[href^="#"]` intercept) → F5. Search + day-route → F6. Leaflet island, image-fallback, notes → F7. Parity suite → F8.

## Scope

**IN F3 (this contract covers visual + interaction for):**
- **Layout shell** componentized verbatim: `Topbar` (brand + `ThemeToggle`), `NavPills` (hybrid: 7 structural + 5 derived day pills), `BackButton` (visual shell, mounted-but-hidden), footer.
- **Full `#inicio`**: masthead (decoration, `<h1>` with `<em>`, meta, quote) + info-cards grid (`trip.infoCards`) + "Cómo usar esta guía" (`trip.howTo`).
- **Page scaffold** of ALL section anchors (`#inicio … #arquitectura`) as minimal placeholders carrying their `id`.
- **FOUC-free theme** (D-08…D-10): 2-state `ThemeToggle`, CSS-only icon, verbatim head.

**OUT (other phases — placeholders only, no visual/interaction spec here):**
| Surface | Phase |
|---------|-------|
| Card / timeline / reference rendering, pace modes (`pace-wrap`, `light-toggle`, `resumen-toggle`), `search-wrap` | F4 (search behavior F6) |
| Scroll-to-card, back-stack behavior, scrollspy `+130`, `.nav-pill.active`, `a[href^="#"]` intercept | F5 |
| Search dropdown logic + day-route button | F6 |
| Leaflet map island, image-with-fallback, per-card notes | F7 |
| Parity verification suite | F8 |

> **`#inicio` carries DOM placeholders** (no `id`, no behavior in F3) for `search-wrap`, `pace-wrap` and the two `light-wrap` toggles so the masthead → info-grid spacing/border rhythm matches the golden. Those interactive blocks are wired in F4/F6. Their presence is a layout-parity concern only; do not implement their handlers in F3.
