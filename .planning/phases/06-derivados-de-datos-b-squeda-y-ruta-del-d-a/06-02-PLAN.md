<critical_haystack_rule>
SC#1 requires the search to find "AT LEAST what it found today". The original haystack was `card.textContent.toLowerCase()` — the ENTIRE visible text of the `<article class="card">` (index.html:6439). The schema splits that visible text across many fields. The CONTEXT shorthand ("prose + italian + facts + caption") UNDER-specifies it and would regress SC#1 (e.g. a query for the badge word "Sorrentino" or "Caravaggio", or an arch-style label word like "Tardobarroco", matched in the live site via `card.textContent` but would miss if those fields are excluded). `buildHaystack` MUST be a SUPERSET: include `name`, `italian`, `roman`, `badge`, every `sections[].heading` + `sections[].body` (the body already embeds the detail-photo caption + detail-list bullets as inline MDC), all `facts[].label` + `facts[].value`, `sorrentino.label` + `sorrentino.text`, every `culture[].title` + `culture[].text`, and every `artists[]`/`arch[]` `label` + `note`. A superset is safe; a subset is a regression (RESEARCH §Pitfall 1).
</critical_haystack_rule>
